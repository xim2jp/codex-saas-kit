# Marketing Site Playbook

SaaSの月額定額モデルを売るための営業ポータルサイト設計の方法論。野口さんの「SaaS量産」戦略を支える。

## 【v0.8.0】SDLCフローへの組み込み（Phase 9 モックアップ必須）

営業ポータルサイトは SDLC の**必須タスク**として2段階で作る：

1. **Phase 9（外部設計）— モックアップ（必須）**：先に visual-director がデザインイメージ画像とスタイルガイドを準備・適合確認し、marketing-site-builder がモックアップモードで `docs/15-marketing-site/mockups/` に自己完結HTMLモックを作成（必須5ページ：トップ/LP・機能紹介・スクリーンショット集・料金表・FAQ。運営者紹介・お問い合わせ・法務は簡易可、index.html に8ページサイトマップを明示）。Phase 10 で ui-mockup-reviewer がアプリ画面モックと合わせてレビューする。スキップは要件定義に「営業サイト不要」が明記されている案件のみ
2. **本実装（実装フェーズ以降）**：visual-director のスタイルガイド確定後、承認済みモックを土台に Next.js で本実装（本書の以降の方法論を適用）

モック段階から本書の「必須ページ」「LP構成」「CTA階段」の考え方を反映しておくと、本実装での手戻りが減る。

## 営業ポータルサイトの構成要素

### 必須ページ（v0.9.0 改訂：8ページ構成）

1. **トップページ（LP）**：ファーストインプレッション、Hero、価値訴求
2. **機能紹介**：主要機能の説明（3-5機能、各機能1ページ or セクション）
3. **運営者紹介**：信頼性の核。**https://shinichi.noguchi.jp.net から写真含め引用**して構成する（引用元を固定ソースとし、案件ごとに書き起こさない）
4. **スクリーンショット集**：SaaSは「画面がプロダクトそのもの」。実画面のスクリーンショットをギャラリー形式で見せる（実装前はアプリ画面モックのスクショで代用し、実装後に実画面へ差し替え）
5. **料金表**：プラン比較、CTA
6. **FAQ**：購入前の不安解消
7. **お問い合わせ**：フォーム or メールリンク（CV導線の受け皿）
8. **法務**：特定商取引法に基づく表記・プライバシーポリシー・利用規約（法的必須。legal-docs-generator の成果物を掲載）

### ビジュアル方針の傾向（厳格ルールではないが目指す方向）

- **幾何学的・抽象的なイラストよりも、写実的な画像を優先する**。装飾目的の抽象アートで埋めない
- **SaaSなので「実際の画面」が最強の訴求素材**。トップ・機能紹介・スクリーンショット集では、プロダクトの画面スクリーンショットを極力多用する（Playwright で撮影した実画面／モック段階ではアプリ画面モックのスクショ）
- AI生成画像を使う場合も写実寄り（photorealistic）を基本とし、UIモックの代用にはしない（従来ルールどおり）

### 推奨ページ

9. **導入事例**：社会的証明（最初は数件でもOK）
10. **ブログ / 知見**：SEO目的
11. **ヘルプ・ドキュメント**：ユーザーが自力で解決できる
12. **お問い合わせ**：購入前相談、デモ申し込み
13. **比較表**：競合との違い（必要に応じて）

## トップページ（LP）の構造

### 王道構造（B2B SaaSテンプレ）

```
1. Hero（ファーストビュー）
   - 強いキャッチコピー（一文）
   - サブコピー（解決する課題）
   - CTAボタン（無料トライアル / 資料請求 / デモ予約）
   - 信頼バッジ（導入企業ロゴ・実績数値・受賞歴）

2. 課題提起
   - ターゲットの困りごと（3-5個）

3. ソリューション
   - 提供価値の概要（一文）
   - キービジュアル（製品スクリーンショット）

4. 主要機能（3-5個）
   - 各機能：見出し + 1-2文の説明 + 画像 or アイコン

5. 導入事例（社会的証明）
   - 導入企業のロゴ、ユーザーの声、定量効果

6. 価格表（簡易版）
   - 主要プラン2-3個、詳細は専用ページへ

7. FAQ（上位3-5問）
   - よくある質問の抜粋

8. 最後のCTA
   - もう一度トライアル / お問い合わせを促す

9. フッター
   - 法定表記リンク、SNS、ナビ
```

### コピーライティングの原則

- **一文で価値を伝える**：「○○な△△を解決」
- **業界用語を使わない**：ターゲットが理解できる言葉
- **数値を入れる**：「3倍効率化」「100社が利用」
- **具体的なシーン**：「シフト作成に毎週3時間→10分に」
- **怒り・苦しみを言語化**：「またExcelで管理してませんか？」
- **CTAは強い動詞**：「無料で始める」「資料を受け取る」

### 避けるべきパターン

- 抽象的な美辞麗句（「革新的な」「次世代の」「最先端の」）
- 機能の羅列（「○○機能」「××機能」だけ並べる）
- 自社目線（「我々は」より「あなたの」）
- CTAが弱い（「詳しく見る」より「無料で始める」）

## 価格ページの設計

### プラン構造（推奨：3プラン）

```
[Starter]              [Pro] ⭐ 人気        [Enterprise]
無料 or 低額            標準価格              要問い合わせ

スモールチームに         成長中のチームに      大規模・特殊要件

機能リスト              機能リスト            機能リスト
（基本のみ）            （Starter +α）       （Pro +α）

[無料で始める]          [プロで始める]        [お問い合わせ]
```

### 表示すべき情報

- **月額 / 年額の選択**（年額は割引、デフォルトは月額）
- **税込 / 税別の明示**（B2B案件では税別が一般的）
- **「適格請求書発行事業者」**の表記（B2B顧客には強い訴求）
- **無料トライアル期間**（あれば）
- **解約条件**（「いつでも解約可能」は重要）
- **支払い方法**（クレジットカードのみか、銀行振込も対応か）
- **比較表**（プラン別機能対応）

### CTA ボタン

- Starterは「無料で始める」など心理負担低く
- Proは目立つデザイン（推奨マーク付き）
- Enterpriseは「お問い合わせ」（営業対応）

### 比較表のチェックポイント

各プランで比較する項目を**横並び**で：

- ユーザー数上限
- 主要機能（◯/△/×で表記）
- ストレージ・データ量
- サポート種別
- SLA
- カスタマイズ可否

## FAQ ページ

### よくある質問のカテゴリ

1. **料金・支払い**
   - 月額？年額？
   - 解約は？
   - 返金は？
   - 領収書・請求書は？（**適格請求書発行**を明記）
   - 支払い方法は？

2. **機能・使い方**
   - 〇〇はできる？
   - △△との連携は？
   - データ移行は？

3. **セキュリティ**
   - データ保管場所
   - 暗号化
   - バックアップ
   - SOC2 / ISO27001（あれば）

4. **サポート**
   - 問い合わせ方法
   - 営業時間
   - SLA

5. **法的・契約**
   - 利用規約
   - プライバシー
   - データ削除

### 書き方

- 1問1答、簡潔に
- 答えを最初に書き、補足は後
- 重要な質問を上位に
- 検索可能なキーワード入り

## SEO 対策

### 技術 SEO（実装で対応）

- Server-side rendering（Next.js App Router）
- メタタグ（title, description, OG）
- 構造化データ（JSON-LD）
- sitemap.xml / robots.txt
- 画像最適化（Next/Image）
- Core Web Vitals（LCP, FID, CLS）

### コンテンツ SEO

- ターゲットキーワード調査
- 検索意図に応えるページ構成
- 内部リンク戦略
- ブログ・知見記事の継続発信

## CTA（コンバージョン）設計

### 階段モデル

訪問者の検討段階に応じた CTA：

1. **認知段階**：「資料ダウンロード」（メアド取得）
2. **興味段階**：「無料デモ予約」「ウェビナー申込」
3. **検討段階**：「無料トライアル」（カード不要）
4. **決定段階**：「契約する」（Stripe Checkoutへ）

複数の CTA を**ページ内に複数配置**：Hero、機能紹介後、価格表、FAQ後、フッター直前。

### Stripe Checkout 連携

```typescript
// app/api/checkout/route.ts
export async function POST(req: Request) {
  const { priceId } = await req.json();
  
  const session = await stripe.checkout.sessions.create({
    mode: 'subscription',
    line_items: [{ price: priceId, quantity: 1 }],
    success_url: `${process.env.NEXT_PUBLIC_URL}/welcome?session_id={CHECKOUT_SESSION_ID}`,
    cancel_url: `${process.env.NEXT_PUBLIC_URL}/pricing`,
    subscription_data: {
      trial_period_days: 14,
    },
    locale: 'ja',
  });
  
  return Response.json({ url: session.url });
}
```

### 価格表からのフロー

```
[価格ページ] → [プラン選択ボタン] 
   → POST /api/checkout 
   → Stripe Checkout（外部）
   → 決済成功 → /welcome（オンボーディング）
   → 決済キャンセル → /pricing
```

## 特定商取引法に基づく表記

SaaS の場合の必須記載項目：

- 販売事業者の名称
- 所在地
- 連絡先（電話・メール）
- 販売価格（税込）
- 商品代金以外の料金
- 支払い方法
- 支払い時期
- 商品の提供時期
- 返品・キャンセル
- 動作環境

野口さんの場合：
- 販売事業者：野口慎一（屋号があればその名称も）
- 所在地：練馬区旭丘一丁目（具体的な住所は要法務確認）
- 適格請求書発行事業者：T...（番号）

## 競合分析の進め方

新しいSaaS案件で営業サイトを作る際の調査：

1. **直接競合**：同じ業界・同じ機能のSaaS（3-5社）
2. **代替手段**：Excel / 紙 / 人手作業
3. **間接競合**：別アプローチで同じ課題を解決

各社の：
- 価格帯
- 主要機能
- ターゲット
- 強み・弱み
- LPの構成

を**Notion or スプレッドシート**にまとめる。
