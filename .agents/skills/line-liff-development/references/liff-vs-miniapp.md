# LIFF アプリ vs LINE ミニアプリ — 方式選定とチャネル構成

要件定義・技術選定の段階で「どちらを作るか」「どのチャネルが要るか」を確定するための判断材料。

## 全体像

```
LINE プラットフォーム
├── LINE ログインチャネル ──── LIFF アプリ（汎用）
├── LINE ミニアプリチャネル ── LINE ミニアプリ（LIFF の特別カテゴリ）
└── Messaging API チャネル ── LINE 公式アカウント / Bot（Webhook・push）
```

- **LIFF（LINE Front-end Framework）**：LINE アプリ内ブラウザで動く Web アプリの仕組み。HTML/CSS/JS（= Next.js でよい）で作り、LIFF SDK で LINE のユーザー情報・メッセージ送信・QR などにアクセスする。
- **LINE ミニアプリ**：LIFF をベースに、LINE が用意した「ミニアプリ」という枠組みに乗せたもの。専用チャネル・専用機能・LINE 内での発見性を持つ。

> **要点：ミニアプリは LIFF の上位概念ではなく、LIFF の特別な一形態。** 技術的な土台（LIFF SDK・Next.js）は共通で、「チャネル種別」と「使える機能・公開フロー」が違う。

## 比較表

| 観点 | LIFF アプリ | LINE ミニアプリ |
|------|-----------|----------------|
| チャネル | LINE ログインチャネル | LINE ミニアプリチャネル（専用） |
| 公開審査 | 不要（Web アプリを登録するだけ） | 2024-11-28 以降、公開前審査は**必須でなくなった**。ただし品質ガイドラインは順守 |
| 友だち追加 | 機能によっては必要 | **不要で利用可**（リーチが広い） |
| 発見性 | リンク / リッチメニュー / QR から | 上記＋ LINE 内での導線 |
| サービスメッセージ | 使えない | **使える**（無料・操作への応答として） |
| パーマネントリンク | — | あり（共有・QR・POP 用） |
| トーク内シェア | `shareTargetPicker` 等 | 同上＋ミニアプリ向けの導線 |
| 向くケース | 特定の公式アカウント友だち向け機能、社内 / 限定向け | 広く一般に配る生活サービス（予約・会員証・電子レシート等） |

## 方式選定フロー

```
1. LINE 上で動かす必要があるか？
   No → 通常の Web（Next.js）。LINE ログインは auth-integration skill で OAuth ボタンとして
   Yes ↓

2. 不特定多数に広くリーチしたい / 友だち追加の摩擦をなくしたいか？
   Yes → LINE ミニアプリ
   No（特定の公式アカウント友だち向け）→ LIFF アプリ

3. サービスメッセージ（無料の操作応答通知）やパーマネントリンクが要るか？
   Yes → LINE ミニアプリ一択

4. Bot として能動的にメッセージを送る（push・リッチメニュー・自動応答）必要があるか？
   Yes → Messaging API チャネルも併設（LIFF / ミニアプリと併用）
```

> **野口さん向けの目安**：地域コミュニティ・店舗系の B2C 案件（会員証、予約、ポイント、電子レシート、順番待ち）は**ミニアプリ**が有利。特定企業の社内向け・公式アカウント友だち限定の機能は **LIFF アプリ**で十分。

## チャネル構成の決め方

LINE Developers Console で「プロバイダー」配下に「チャネル」を作る。案件で要るものを ADR に列挙する。

| 必要なもの | 作るチャネル |
|-----------|------------|
| LIFF アプリ（ログイン・プロフィール取得） | LINE ログインチャネル（LIFF アプリを登録） |
| LINE ミニアプリ | LINE ミニアプリチャネル |
| Bot（Webhook 受信・push・リッチメニュー） | Messaging API チャネル |
| 公式アカウント | LINE 公式アカウント（Messaging API チャネルと紐づく） |

- 1 案件で複数チャネルを併用するのが普通（例：ミニアプリチャネル + Messaging API チャネル）。
- チャネルごとに ID / シークレット / アクセストークンが分かれる。**取り違えると認証が通らない**ので、環境変数名にチャネル種別を含める（例：`LINE_MINIAPP_CHANNEL_ID` / `LINE_MESSAGING_CHANNEL_SECRET`）。

## LIFF アプリの「サイズ」設定

LIFF アプリ登録時に表示サイズを選ぶ：

| サイズ | 用途 |
|--------|------|
| `full` | 画面いっぱい。本格的なアプリ画面 |
| `tall` | 画面の約 8 割。フォーム・一覧など |
| `compact` | 画面下部の小窓。簡単な確認 |

- 設計段階（external-designer）で画面ごとに適切なサイズを決める。後から変えると体験が崩れる。

## ネイティブアプリ（Expo）との使い分け

| 条件 | 推奨 |
|------|------|
| LINE ユーザーがターゲットのほぼ全員、LINE 内で完結してよい | **LIFF / ミニアプリ** |
| プッシュ通知・カメラ・生体認証など OS ネイティブ機能が中核 | ネイティブ（`mobile-app-development` skill） |
| アプリストアでのブランド・発見性が重要 | ネイティブ |
| 両方欲しい | Next.js Web + LIFF をベースに、必要なら Expo を追加（コード共有層を設計） |

## ADR に残す項目

`docs/11-tech-stack/adr/NNNN-line-platform.md` に：

- 採用方式：LIFF アプリ / LINE ミニアプリ
- 作成するチャネル一覧
- Messaging API 連携の有無（Bot 機能）
- LIFF アプリのサイズ
- ホスティング（Vercel 想定）とエンドポイント URL の方針
- 決済の方式（外部 Stripe / LINE Pay / なし）
- 通常 Web 版も並行提供するか（コード共有の方針）
