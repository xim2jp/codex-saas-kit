# LINE ミニアプリの開発と公開

LINE ミニアプリ固有の事項（チャネル、サービスメッセージ、パーマネントリンク、公開フロー）。LIFF アプリ共通部分は他の reference を参照。

## ミニアプリチャネルの基本

- ミニアプリは **LINE ミニアプリチャネル**に属する（LIFF アプリの LINE ログインチャネルとは別）。
- 開発の土台は LIFF と同じ：Next.js + `@line/liff`（`references/setup-and-nextjs.md`）。
- **チャネルアクセストークン**：ミニアプリチャネルでは**ステートレスチャネルアクセストークンの利用が推奨**。長期チャネルアクセストークンや任意有効期間の v2.1 トークンは使えない。トークン取得処理はこれに合わせて実装する。

## 公開フロー

```
1. LINE Developers Console でミニアプリチャネル作成
2. 開発（LIFF と同じ。Next.js + LIFF SDK）
3. チャネル設定（アイコン、名称、説明、エンドポイント URL、scope）
4. 公開設定 → 公開
```

- **公開前審査**：2024-11-28 以降、公開前の審査は**必須ではなくなった**。これによりミニアプリの公開ハードルは下がった。
- ただし**ミニアプリのデザイン・品質ガイドライン**は順守する必要がある（LINE のブランド・UX 規約、禁止事項）。実装時に LINE Developers の最新ガイドラインを確認する。
- ステータス（開発中／公開）をチャネルで管理する。検証用と本番用でチャネル／ミニアプリを分けるのが安全。

## パーマネントリンク

ミニアプリ（および特定ページ）を共有するための恒久的な URL。

- ミニアプリやその特定ページを **QR コード・サービスメッセージ・POP（店頭物）**で共有する時に必要。
- ヘッダのアクションボタンからページを共有すると、そのページのパーマネントリンクが自動生成される。
- 店舗系案件では「店頭 POP の QR → ミニアプリの該当ページ」という導線をパーマネントリンクで作る。
- ディープに特定ページへ着地させたい場合、パーマネントリンクの構造（クエリ／パス）を外部設計で決める。

## サービスメッセージ

ミニアプリだけが使える、ユーザーのトークに送る**無料**のメッセージ。

### 使ってよい範囲（重要）

- サービスメッセージは、**ユーザーの操作に対する確認・応答**としてのみ送れる（例：予約完了、受付番号の発行、注文確定）。
- **宣伝・販促・一斉配信に使ってはいけない**。規約違反になる。販促は Messaging API の通常メッセージ（友だち向け）で行う。

### 制約

- **テンプレート**：ミニアプリチャネルごとに**最大 20 種類**のサービスメッセージテンプレートを登録できる。送信は登録済みテンプレートで行う。
- **サービス通知トークン**：発行から **1 年間（31,536,000 秒）有効**。1 トークンにつき**最大 5 通**のサービスメッセージを送れる。
- 送信のたびにトークンの残量・有効期限を考慮した実装にする。

### 設計のポイント

- 「どのユーザー操作に、どのテンプレートで、何通返すか」を外部設計で洗い出す（20 テンプレート・5 通/トークンの枠に収める）。
- 友だち追加なしでも使える点がミニアプリの強み。サービスメッセージで再訪導線・完了通知を作る。

## ミニアプリならではの体験設計

- **友だち追加なしで利用可**：初回利用の摩擦が小さい。オンボーディングを軽く。
- **トーク内シェア**：`shareTargetPicker`（`references/liff-features.md`）やパーマネントリンクで拡散導線を作る。
- **公式アカウント連携**：push 通知や販促を送りたいなら、ミニアプリ利用者を公式アカウントの友だちにする導線（`requestFriendship`）を別途用意する。
- **店頭・オフライン連携**：QR・POP からの起動が多い。パーマネントリンクと着地ページの設計が肝。

## 決済

- ミニアプリ内の課金は、案件要件で方式を選ぶ：
  - **外部決済（Stripe）**：物販・サービス料金。`stripe-integration` skill と連携。LINE 内ブラウザでの Stripe Checkout の挙動を検証する。
  - **LINE Pay**：LINE 経済圏で完結させたい場合。
- ネイティブアプリの IAP 規約（`mobile-app-development` skill）とは別物。ミニアプリは Web なのでストア IAP の制約は受けない。

## 公開チェックリスト

- [ ] ミニアプリチャネルが作成され、本番／検証で分離されている
- [ ] ステートレスチャネルアクセストークンで実装している
- [ ] LINE のミニアプリ品質・デザインガイドラインを確認・順守
- [ ] アイコン・名称・説明・スクリーンショット等のメタdata を用意
- [ ] エンドポイント URL が本番環境を指している（HTTPS）
- [ ] パーマネントリンクの設計（着地ページ・QR 導線）が済んでいる
- [ ] サービスメッセージが「操作への応答」に限定され、販促に使われていない
- [ ] サービスメッセージのテンプレート数（≤20）・送信通数（5/トークン）が枠内
- [ ] 決済方式（Stripe / LINE Pay / なし）が確定し、LINE 内ブラウザで検証済み
- [ ] プライバシーポリシー・利用規約が公開 URL にある
