# Paid Ads Toolkit Skill

SaaS の集客を **SNS 広告を中心とした有料広告**で加速するための知識集。SEO・AIOだけでは検索需要そのものが競合に埋もれるカテゴリや、指名検索が育つ前の立ち上げ期に、**即効性のある集客チャネル**を設計・運用する。

> **このSkillのゴール**：野口さんが量産する月額 SaaS が、①競合の多いカテゴリでも新規獲得を止めずに済み、②CAC が LTV に見合う範囲でスケール判断ができ、③一括払いのみ・分割借入不可という財務制約の中で広告費が制御不能にならない状態を作る。

## 重要原則

### 1. SEO/AIOと広告は「役割分担」であって代替ではない

`seo-toolkit` は中長期の資産構築（無料・複利的に効く）、本Skillは**即効性のある需要の刈り取りと新規獲得の底上げ**。競合カテゴリが飽和して指名検索が育つまで待てない、あるいはSEOの検索需要自体が小さいニッチSaaSでは、**広告を主戦力に据える判断も正当**。両者の予算配分はゼロサムではなく、SEOで作ったLPを広告の受け皿にするなど相互に強化する。

### 2. 財務制約を最優先で設計に織り込む（野口さん固有・最重要）

民事再生中で**一括払いのみ・借入/分割不可**。SNS広告のほとんどは**クレジットカードによる後払い（与信枠依存）**が標準であり、この与信リスクを事前に潰さないと運用自体が破綻する。

> **基本方針：与信枠に依存しない支払い方式（プリペイド/デビット/請求書前払い）を優先し、確保できない媒体・キャンペーン形態は導入を見送るか少額に限定する。** 詳細は `targeting-and-budget.md`。

### 3. 少額テスト → 学習 → 段階的スケールの順序を守る

いきなり大きな予算を投じない。**媒体・クリエイティブ・ターゲティングの組み合わせを小さく検証してから拡大**する。テスト予算の目安・学習に必要な最低コンバージョン数・スケール条件は `targeting-and-budget.md` と `cac-ltv-and-scaling.md` に従う。

### 4. CAC は必ず LTV と対で管理する

広告費だけを見て「安い/高い」を判断しない。**CAC ÷ LTV の回収期間**で投資判断する。`pricing-strategist` の価格設計、`cost-guardian` の原価試算と接続し、赤字覚悟のダンピング獲得にならないようにする。撤退基準（ROAS/CACのしきい値）を事前に決め、感情でキャンペーンを続けない。

### 5. クリエイティブは量産・疲労対策込みで設計する

SNS広告は**クリエイティブの消耗が速い**（同じ広告を同じユーザーに出し続けると効果が落ちる＝Ad Fatigue）。1本作って終わりではなく、`promo-video-producer` / `visual-director` と連携してテンプレ化・量産できる体制を最初から作る。

### 6. コンプライアンスは公開前に必ず確認する

SaaSの「効果」を誇張する表現は**景品表示法（優良誤認・有利誤認）**に抵触しうる。インフルエンサー起用やUGC風広告は**ステルスマーケティング規制（2023年10月施行）**の対象になりうる。各SNSプラットフォームの広告ポリシーも随時変わる。`compliance-and-platform-policy.md` を毎回参照し、`legal-docs-generator` の特商法表記と整合させる。

## 他領域との接続

- **SEO/AIO**：中長期の SEO 戦略と短期の広告戦略の予算・優先度を一緒に決める。広告の受け皿 LP も title / OG / 構造化データを満たし `seo-plan.md` と整合させる
- **クリエイティブ制作**：動画・静止画の制作側にはフォーマット要件（尺・アスペクト比・冒頭フック秒数）を渡して量産を依頼する。`visual-style-guide.md` / `design-system.md` は広告でも尊重する
- **価格・コスト**：CAC の許容上限は LTV（`pricing-strategy.md` のプラン単価 × 継続期間）から逆算する。広告予算は `cost-estimate.md` のランニングコストに計上し、一括払い前提の年間試算に含める
- **LP 実装**：受け皿 LP の実装依頼には UTM 計測と Pixel の設置箇所を明示する
- **法務**：広告文言の景品表示法チェックと、特商法表記へのリンク整合を確認する
- **計測**：ファネル定義・一般的なイベント計測は `analytics-integration` に任せ、本 Skill は広告特有の計測（Pixel / Conversions API）だけを扱う

## 野口さん固有のチェック

- [ ] 広告アカウントの支払い方式が与信枠に依存しない形（プリペイド/デビット/前払い）になっているか、依存する場合はリスクを明示しているか
- [ ] テスト予算が少額から始まり、成果を見てから段階的にスケールする設計になっているか
- [ ] CAC が LTV との対比で管理され、撤退基準（ROAS/CACしきい値）が明記されているか
- [ ] SEO/AIO（`seo-toolkit`）との予算・優先度のバランスが検討されているか（広告一辺倒/SEO一辺倒になっていないか）
- [ ] クリエイティブの量産・疲労対策の体制があるか（1本作って終わりになっていないか）
- [ ] 景品表示法・ステマ規制のチェックを経ているか
- [ ] 1名運用で回せる運用頻度（毎日の入札調整等を前提にしていないか）になっているか

## アンチパターン（よくある失敗）

1. **与信枠に依存する支払い方式のまま大きな予算を投じる**：民事再生中の財務制約と致命的に相性が悪い
2. **テストなしにいきなり本予算を投入する**：学習データが無いまま広告費を溶かす
3. **CACだけ見てLTVと対比しない**：獲得コストが利益を食う赤字獲得に気づかない
4. **クリエイティブを1本作って回し続ける**：Ad Fatigueで効果が急落しても気づかない
5. **SEOと広告を同時に始めて両方中途半端にする**：競合過多カテゴリでは広告優先、育っている指名検索があるならSEO優先、と優先度を明確にする
6. **誇張表現をそのまま広告文言にする**：景品表示法違反のリスク
7. **インフルエンサー起用時に広告表記を怠る**：ステマ規制違反
8. **撤退基準を決めずに惰性でキャンペーンを続ける**：感情的な予算配分になる
9. **1名運用の運用頻度を無視した複雑な入札戦略を組む**：日次調整が必要な設計は破綻する
10. **プラットフォームの広告ポリシーを確認せず出稿し却下される**：ヘルスケア/金融隣接カテゴリは特に事前確認必須
