# Customer Support Toolkit Skill

野口さんが**1名で複数の月額SaaSを並行運用**しながらカスタマーサポートを破綻させないための知識集。ヘルプセンターの自動生成、AIによる問い合わせ一次応答、FAQの自動更新までを、量産・横展開しやすい形で扱う。サポートは実装フェーズ以降〜運用フェーズにかけて継続する横断的関心事である。

> **ゴール**：新しいSaaSを1つ立ち上げるたびにサポート体制をゼロから作らず、**docs/ の設計資産とログデータから自動生成・自動更新**される仕組みで、1名運用のまま複数プロダクトの問い合わせ対応品質を維持する。

## 原則

### 1. サポートは「作る」のではなく「生成する」

1名運用で複数SaaSのヘルプセンターを個別に手書きするのは持続不可能。**要件定義書・機能一覧・画面設計（docs/）を単一の情報源とし、ヘルプ記事を自動生成・自動同期する**のが基本方針。手書きは「生成できない微妙なニュアンス」の加筆修正に限定する。ヘルプセンターの画面一覧・情報設計（カテゴリ階層・検索導線）は `docs/20-external-design/` に反映する。

### 2. AIの一次応答は「答える」より先に「答えて良いか」を判定する

Claude API（既定は Claude Sonnet 5.5、モデル ID `claude-sonnet-5-5`）による自動応答は**回答範囲を明示的に区切り**、範囲外・自信がない・返金や法的判断を伴う問い合わせは即座に人間（野口さん）へエスカレーションする。ハルシネーションによる誤回答は複数SaaSの信頼を同時に毀損するため、**保守的な設計を優先**する。エスカレーション時のユーザー向け文言とフォームのエラー処理も設計対象に含める。詳細は `ai-first-response.md`。

### 3. 野口さん財務制約：Claude APIコストは無制限にしない

民事再生中・一括払いのみ・借入不可。Claude API は無料枠が存在しないため、**問い合わせ1件あたりのコストを見積もった上で使用量に上限を設ける**（レート制限・月次予算アラート・キャッシュ活用）。ランニングコストが読めないまま複数SaaSに展開しない。複数SaaS横断のコスト監視と接続できるよう、上限設計は `ai-first-response.md` の方針に揃える。

> **基本方針：AI一次応答は「よくある質問への即答」に絞り、複雑な調査・過去ログ全件参照など高コストな処理は人間対応にフォールバックする。**

### 4. 1名運用は「承認フローの軽量化」で回す

FAQ更新もエスカレーション対応も、レビュー・承認者が野口さん1人。多段階の承認フローは不要で、**候補の自動生成 → 野口さんの最終確認 → 即反映**の一段階フローに簡略化する。詳細は `faq-maintenance.md`。

### 5. 複数SaaS間でテンプレートを再利用する

ヘルプセンターの構造（カテゴリ体系・記事テンプレート・検索UI）、AI一次応答のプロンプト骨格、FAQ抽出パイプラインは**プロダクト固有部分とプロダクト非依存部分を分離**し、後者はSaaS間で使い回す。新規SaaS立ち上げ時のサポート整備を数時間〜数日に短縮する。

### 6. AI一次応答の品質は数字で監視する

誤回答率・エスカレーション率をダッシュボードで追う場合は `observability-integration` Skill と併用する。レビューでは回答範囲逸脱・エスカレーション漏れ・PII 混入と、レート制限・コスト上限の実装有無を確認する。

## 野口さん固有のチェック

- [ ] ヘルプ記事が docs/（要件定義書・機能一覧・画面設計）から自動生成/同期される構成になっているか（手書き一辺倒になっていないか）
- [ ] Claude APIの呼び出しにレート制限・月次予算アラートが設定されているか
- [ ] AI一次応答が回答範囲外の質問を検知し、確実に人間（野口さん）へエスカレーションできるか
- [ ] 返金・解約・法的判断を伴う問い合わせがAI単独で完結しない設計か
- [ ] FAQ更新の承認フローが野口さん1人の最終確認で完結する軽量設計か（多段階承認になっていないか）
- [ ] ヘルプセンター/AI一次応答/FAQテンプレートが他のSaaSプロダクトへ横展開しやすい構造か
- [ ] 問い合わせログにPII（氏名・メール・決済情報等）が含まれる場合、保存・AI送信時の取り扱いが適切か

## アンチパターン

1. **SaaSごとにヘルプセンターを手書きでゼロから作る**：1名運用では継続更新が破綻する
2. **AIに回答範囲の制約を設けず全問い合わせに自動応答させる**：誤回答が複数SaaSの信頼を同時に毀損する
3. **エスカレーション基準を定義しない**：AIが答えられない質問を無理に答えてしまう
4. **Claude API呼び出しに使用量上限を設けない**：無料枠がないため想定外のコストが積み上がる
5. **返金・解約・契約関連をAIが単独処理**：金銭・契約に関わる判断は必ず人間を介在させる
6. **FAQ承認フローを多段階にする**：1名運用では承認者が野口さん1人なので不要な重さになる
7. **問い合わせログを分析せず放置**：頻出質問がFAQに反映されず同じ問い合わせが繰り返される
8. **ヘルプ記事とdocs/の内容が乖離する**：機能追加時にヘルプセンターだけ更新漏れになる
9. **AI一次応答のプロンプトをSaaSごとに作り直す**：プロダクト非依存部分を切り出さず量産効率が出ない
10. **PIIを含む問い合わせ内容を無制限にAIへ送信・ログ保存する**：取り扱い方針を決めずに実装してしまう

## 出典・一次ソース方針

このSkillの技術情報は**公式ドキュメントを一次ソース**とする（Anthropic `docs.claude.com`、Next.js `nextjs.org/docs`、Supabase `supabase.com/docs`）。Claude APIの料金・モデル・レート制限、Next.jsのルーティング仕様は更新が速いため、実装直前に各 references の出典URLで最新を再確認すること。各 references ファイル末尾に出典URLを明記している。
