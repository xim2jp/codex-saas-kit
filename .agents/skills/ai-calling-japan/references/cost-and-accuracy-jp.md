# コスト試算と日本語音声認識の精度

「いくらかかるか」「日本語の精度はどうか」「精度をどう上げるか」の指針。

> 価格は変動が激しい。本ファイルの数値は**2026 年時点の概算レンジ**。設計時に各サービスの一次情報で必ず再計算する。

## コストの構造：分（per-minute）課金の積み上げ

AI 通話のコストは**通話時間（分）に比例**して積み上がる。1 分あたりの内訳：

| 要素 | 概算レンジ（USD/分） | 備考 |
|------|---------------------|------|
| テレフォニー（電話網） | $0.01 前後 + 番号月額 | 着信/発信、国内通話。番号は月額レンタル料が別途 |
| STT（音声認識） | $0.005〜0.01 | ストリーミング認識 |
| LLM | $0.01〜0.05 | トークン課金。プロンプトキャッシュで圧縮可。会話 1 ターンは短い |
| TTS（音声合成） | $0.05〜0.10 | 文字数課金。低レイテンシ TTS は単価差あり |
| プラットフォーム手数料（マネージド時） | Vapi 約 $0.05 / Retell 約 $0.07〜 | 自作なら不要 |

**カスケード型の合計：おおむね $0.10〜0.30/分。** マネージドはここに手数料が乗る。

### 音声対話型（Realtime）のコスト

音声トークン課金。OpenAI Realtime 系は、**素のままだと $0.18〜0.46/分**程度になりうるが、**プロンプトキャッシュを効かせツール出力を絞ると $0.05〜0.10/分**まで下がる、という幅がある。用途特化の軽量モデル（翻訳/書き起こし特化）はさらに安い。**音声トークンはテキストより高い**ことを前提に試算する。

### 試算テンプレート

```
月間コスト ≒ 月間通話本数 × 平均通話時間（分）× 分単価
+ 電話番号の月額レンタル料 × 番号数
+ （自作の場合）ECS Fargate などの常駐インフラ費
+ 録音/文字起こしのストレージ費
```

例：月 3,000 本 × 平均 3 分 × $0.20/分 ＝ 約 $1,800/月 ＋ 番号・インフラ・ストレージ。
**ADR には必ずこの試算を添付**し、ユーザーに事前提示する（野口さんは一括払い前提・財務制約あり）。

## 人間のオペレーターとの比較

AI 通話の ROI は「人手のコスト」と比べて語る。**日本のコールセンター/電話対応の人件費は高い**（時給・採用難・教育コスト）。1 席が 1 通話しか捌けない人手に対し、AI は同時並行でスケールする。**日本案件では人件費が高いため AI 通話の費用対効果は出やすい**。一方でコスト暴走を防ぐ装置（後述）は必須。

## コスト暴走を防ぐ装置（必須）

- **最大通話長の上限**：1 通話 N 分で強制終了。無限ループ通話を防ぐ
- **無音タイムアウト**：相手の無言が続いたら終話
- **プロンプトキャッシュ**：システムプロンプト・固定文脈をキャッシュし LLM コストを圧縮
- **モデルの振り分け**：単純な定型フローは小型/安価モデル、難所だけ上位モデル
- **同時通話数の上限**：意図しない大量発信を防ぐ
- **月次の利用上限アラート**：プラットフォーム/クラウドの予算アラートを設定

## 日本語音声認識の精度

### なぜ日本語は難しいか

- **分かち書きがない**：単語境界が曖昧
- **同音異義語が多い**：「以降/移行/意向」「機械/機会」など、文脈なしに確定できない
- **固有名詞**：氏名・地名・商品名は学習データに無いと誤認識しやすい
- **数値**：電話番号・金額・日付・住所の数字列は誤りが致命傷になりやすい
- **電話音声は 8kHz 狭帯域**：情報量が少なく、16kHz 広帯域より精度が落ちる
- **方言・話速・雑音・複数話者**：実環境ではさらに条件が悪い

精度は WER（単語誤り率）で語られる。Deepgram の Nova 系などは日本語ストリーミングで実用域にあるが、**「英語と同じ精度が出る」前提を置かない**。固有語・数値を含む業務会話では必ず実データで評価する。

### 精度を上げる設計（最重要）

1. **重要情報は AI に復唱（復唱確認）させる**
   「お名前は ○○ 様、ご予約は 5 月 20 日 14 時、お間違いないですか？」と AI から確認を取り、相手の肯定で確定する。**誤認識をその場で訂正できる唯一の確実な手段**。
2. **数値は DTMF（プッシュ）フォールバック**
   電話番号・暗証番号など長い数字列は、音声認識でなく**プッシュ操作で入力**させる選択肢を用意する。
3. **キーワードブースト / カスタム辞書**
   商品名・地名・人名・専門用語を STT のブースト機能やカスタム語彙に登録する。
4. **電話音声向け STT モデル/設定**を使う（8kHz・telephony モデル）。
5. **会話を構造化**：オープンな質問より「はい/いいえ」「3 択」に寄せると認識・解釈が安定する。
6. **信頼度（confidence）で分岐**：STT/解釈の信頼度が低いターンは聞き返す、または人間へエスカレーション。
7. **通話後の LLM による補正**：文字起こし全体を LLM で読み直し、文脈から誤認識を訂正・要約・構造化抽出する（リアルタイムでなくてよい処理）。

### レイテンシと精度のトレードオフ

エンドポインティング（無音しきい値）を短くすると応答は速いが、考えながら話す相手の発話を途中で切ってしまい「実質的な認識ミス」になる。セマンティックターン検出の併用で両立を図る（`voice-ai-architecture.md`）。

## 精度の評価（eval）

- **実データでベンチ**：想定ユーザー層・電話品質・固有語を含むサンプルで WER と「タスク成功率」を測る。WER だけでなく「予約が正しく取れたか」を見る
- **シナリオ eval**：LLM 駆動の模擬発信者でシナリオを多数流し、合否を集計（`implementation-and-ops.md`）
- **回帰**：プロンプト・モデル・STT を変えたら eval を再実行し、劣化を検出

## レビュー観点

- [ ] 月間コストを「本数 × 分 × 単価 + 番号 + インフラ + ストレージ」で試算し ADR に添付
- [ ] 最大通話長・無音タイムアウト・同時通話上限・予算アラートを設定
- [ ] プロンプトキャッシュ・モデル振り分けでコストを圧縮
- [ ] 重要情報（氏名・電話番号・金額・日時）の復唱確認を会話設計に組込
- [ ] 長い数値に DTMF フォールバックを用意
- [ ] 固有語をキーワードブースト/カスタム辞書に登録
- [ ] 電話音声（8kHz）の実データで STT 精度を評価済み
- [ ] 信頼度が低いターンの聞き返し/エスカレーションを設計
