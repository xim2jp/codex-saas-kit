## 1. 問題・ニーズ・課題一覧

要求の**源泉**。抽出時は原因・影響を 1 つずつ簡潔に書く（因果分析に深入りしない）。要件定義の後半で §3 の要求と照合し、問題に対応する要求が無いもの／要求に対応する問題が無いものを洗い出す（取りこぼし・膨張の検出）。

| No | 抽出テーマ | 提起者（ロール） | 問題（事実・定量値） | 影響（定量値） | 原因（真因 1 つ） | ニーズ | 課題（解決テーマ） | 対応する要求 BZ | 備考 |
|----|-----------|----------------|---------------------|---------------|------------------|--------|-------------------|----------------|------|
| P-001 | 月次締め業務 | 経理担当 | 月次締めに 6 時間/月かかる | 月末 2 日間は他業務停止 | 売上データを手で転記している（転記 120 件/月） | 締めを半日で終えたい | 手転記を無くす | BZ-003, BZ-011 | 提起者は SEG-01 の代表顧客 |
| P-002 | | | | | | | | | |

問題の原因は**制約（お金・人）に行き着いたら止める**。制約は課題にしない（自分たちで解決できないため）。解決ポイントは「定量効果が大きい」「悪循環を起こしている」問題を優先する。

## 2. 要求構造（OBJ → 業務目的 → 手段）

全要求を「目的」と「手段」に分け、階層で結ぶ。下位が目的なら AND、下位が手段なら AND か OR を明示する（省略時 AND）。**人の手段（運用・ルール）と IT 手段の両方**を置く。妥当性（下 → 上：この手段はこの目的に効くか）と十分性（上 → 下：この手段群で目的は達成できるか）を確認してから §3 を確定する。

```mermaid
flowchart TD
  OBJ01["OBJ-01 6 ヶ月で有料 30 社"]
  BZ001["BZ-001 業務目的：締め作業 6h→1h（2027-01）"]
  BZ003["BZ-003 IT 手段：売上データを Stripe から自動取込"]
  BZ011["BZ-011 業務手段：締め日を月末→翌月 3 営業日に変更（人）"]
  BZ004["BZ-004 IT 手段：（OR）CSV 取込で手転記を半減"]
  OBJ01 --> BZ001
  BZ001 --> BZ003
  BZ001 --> BZ011
  BZ001 -. OR .-> BZ004
```

（任意）企画 OBJ と機能を結ぶリザルトチェーン（IT 施策 → 機能 → 業務への影響 → 中間成果 → 最終成果。前提条件とマイナス影響の打ち消し施策付き）を描く場合もここに置く。

| BZ-012 | IT 手段 | | | | | | | | | | | 先送り（次期） | | |

**採点ルール**（6 基準。粗く 3 段階 → 境界線上だけ精査）：

- 有効性＝目的・目標への貢献（定量効果は算出根拠付き）／必要性＝法制度・内部統制・社会的責任・将来性／緊急性＝期限の有無／費用＝開発費＋**1 名運用の手間と月額ランニング**／実現性＝技術（実績の少ない技術のリスク）と人的（自分で作って運用できるか）／新たな問題＝実現すると生まれる問題とその対処
- 得点化する場合は 5 点満点、**コストは低いほど高得点**、目安は 3 段階、カテゴリ小計を出す。評価は**要求の提示元**が行う
- **採否は優先度と別の列**。値：採用／先送り（次期候補）／棄却（理由）／保留（OQ）。棄却・先送りの行は削除せず残す（蒸し返し防止）

## 4. 業務パターン表（MVP の対象パターン）
