# Requirements Toolkit Skill

曖昧な依頼を、開発着手・投資判断に耐える**要件定義書に変換する**ための知識集。対話の質（プロセス・質問バンク・アンチパターン）と成果物の質（記述規約・文書ガイド・テンプレート・完全性チェック）の両面を支える。

> 基盤：IPA『ユーザのための要件定義ガイド 第2版 — 要件定義を成功に導く 128 の勘どころ』（2019）。企業内大規模プロジェクト向けの記述を、企画・戦略（Phase 1-4）を上流に持つ本フレームワークの Phase 5-6 に再構成した。IPA の「企画工程」＝Phase 1-4、「要件定義工程」＝Phase 5-6、「基本設計（外部設計）」＝Phase 7-10 に対応する。

## 使う場面

- 要件を作る：上流突合 → 現状・問題・課題 → 業務目的・手段 → 具体化 → 優先順位・採否 → UC・NFR・権限 → 推敲 → 完全性確認 → Handoff
- 要件を判定する：記述規約・文書ガイド・完全性チェックリストをレビューの判定基準にする
- 着手を判断する：決まらない要件・中止選択肢・投資材料、要求量と変更要求の扱いを決める
- 下流で読む：BZ・UC・NFR を入力にするとき、ID の意味と粒度を確かめる

## 重要原則

1. **要件定義は企画から始まらない**。経営レベルの目的（OBJ）・ターゲット（SEG）・収益モデル・KPI は Phase 1-4 で確定済み。Phase 5 は**確認して転記**し、聞き直さない。矛盾は OQ にして上流に差し戻す
2. **問題・課題・目的・目標・手段の 5 語を厳密に使い分ける**。要求には「〜を達成したい（目的）」と「〜を実施したい（手段）」の 2 種類があり、業務目的（BZ）を抜いた「中抜け」を禁止する
3. **「現行踏襲」を要求として受け入れない**。現行を書き下ろし、To-Be でも必要な根拠を付ける
4. **目標は測れる形で**。測定尺度・現状値・目標値・達成時期。述語は MEDIC（維持・廃止・削減・増加・創出）。「強化」「改善」禁止
5. **業務手段を IT 手段と同じ重みで検討する**。作らない選択肢（運用・サポート・既存 SaaS）を必ず候補に入れる。難しい判断ロジックは人に残す方が安く柔軟
6. **要求は捨てる・先送りする**。6 基準で粗く判定し、採否列を優先度と別に持つ。棄却・先送りは理由付きで残す。60 点で出して育てる
7. **業務ルールは自然言語の長文で書かない**。表・式・デシジョンテーブル・状態遷移図・CRUD 表に落とす。記述規約（writing-rules.md）に従い、禁止語は Grep で 0 件にする
8. **質問バンクは全部聞かない**。プロセスの各ステップで必要な問いだけ選ぶ。1 ターン 3 問以内、5 問ごとに復唱
9. **判断は decision-log に即記録**。要求の採否・変更要求・未決の取り扱いも含めて「なぜこの仕様になったか」を追跡可能にする
10. **決まらない要件を放置しない**。OQ に全件列挙し、影響評価と先送り基準を満たすものだけ持ち越す。完了判断では中止・棚上げも選択肢に入れ、投資額・回収額の甘い自己査定を疑う
11. **文書間は ID で結び、機械的に整合を確認する**。OBJ → BZ → UC/NFR/ROLE → F → S/API/ENT → テスト。従属値一致・重複・参照元存在の 3 チェック。システム化しない要求も台帳に残す
12. **成果物は `docs/03-requirements/` に配置**（sdlc-toolkit の artifact-layout.md・document-catalog.md に従う）。作る文書は document-set.md で確定したものだけ。無い文書には理由を書く

## 成果物の作成順（Phase 5）

```
0. upstream-reconciliation.md（突合）           ← 対話前に完成（business-strategy-toolkit）
1. requirements.md §0〜§4（文書構成・概要・上流転記・ステークホルダ・現状）
2. business-requirements.md §1〜§3（問題・課題 → 要求構造 → BZ 目的・手段）
3. glossary.md（管理対象の MECE・禁止語）／requirements.md §7（概念データモデル・状態遷移）
4. business-requirements.md §3.2 採否・§4 業務パターン → requirements.md §6 スコープ（MVP・先送り・やらないこと）
5. use-cases.md／permissions-matrix.md／non-functional.md（SR）／requirements.md §9 外部 I/F・§13 運用・移行・§14 受入
6. open-questions.md／decision-log.md（随時）
7. writing-rules §7 推敲 → completeness-checklist → Self-Check → Handoff（上流差し戻し候補・決まらない要件・中止検討・投資材料）
```
