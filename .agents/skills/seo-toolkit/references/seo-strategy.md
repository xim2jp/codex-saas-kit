# SEO 戦略：キーワード・検索意図・コンテンツ設計・E-E-A-T

検索流入の上流。**誰の・どんな検索に・どのページで応えるか**を決める。技術が完璧でも、ここが空白だと順位もAI引用も得られない。

## 1. キーワードの3段モデル（B2B SaaS）

野口さんが量産する月額 SaaS の見込み客は、検討段階によって違う言葉で検索する。3段で網羅する。

| 段階 | 検索の例（シフト管理SaaSの場合） | 狙うページ | CV距離 |
|------|--------------------------------|-----------|--------|
| **課題検索（認知）** | 「シフト作成 大変」「飲食店 シフト 自動化」 | ブログ/知見記事・課題解決LP | 遠い |
| **比較検索（検討）** | 「シフト管理 アプリ 比較」「○○ vs △△」「シフト管理 料金」 | 比較記事・料金ページ・機能ページ | 中 |
| **指名検索（決定）** | 「（プロダクト名）」「（プロダクト名）ログイン」「（プロダクト名）評判」 | トップ・ログイン・導入事例 | 近い |

> **優先順位：まず指名検索（必ず1位を取る）→ 比較検索（CV直結）→ 課題検索（流入量・育成）。** 立ち上げ初期は比較・指名を固め、運用フェーズで課題検索のコンテンツを積む。

## 2. キーワード調査（無料ツールで完結）

有料ツール（Ahrefs/SemRush）がなくても、無料で十分な調査ができる：

1. **Google サジェスト**：検索窓に主軸キーワードを入れ、候補を収集（「〇〇 」でスペース後の候補も）
2. **People Also Ask（他の人はこちらも質問）**：検索結果中の質問群＝そのままFAQ・見出しの種
3. **関連性の高い検索**：検索結果末尾の関連キーワード
4. **Search Console（運用後）**：実際に表示されたクエリ＝最も確実な一次データ。「表示はされるがクリックされない」クエリはタイトル改善の宝庫
5. **競合の見出し**：上位3サイトの `h2`/`h3` を読む＝Google が「この意図に必要」と判断した要素

各キーワードに **検索意図（Informational / Commercial / Transactional / Navigational）** をタグ付けし、応えるページ種別を決める。

## 3. 検索意図とページのマッピング（1ページ1意図）

> **原則：1つのページは1つの検索意図に応える。** 1ページに複数意図を詰めると、どの意図でも中途半端になり順位が出ない。

| 検索意図 | ページ種別 | 構成の型 |
|---------|-----------|---------|
| Informational（知りたい） | ブログ・ガイド | 結論 → 理由 → 手順 → FAQ |
| Commercial（比較したい） | 比較・機能・料金 | 比較表 → 選び方 → 自社の強み → CTA |
| Transactional（使いたい） | 料金・申込・トライアル | 価格 → 保証 → CTA を最短距離で |
| Navigational（特定サイトへ） | トップ・ログイン | ブランド明示・導線最短 |

## 4. トピッククラスタ（内部リンク戦略）

個別記事を孤立させず、**ピラーページ（網羅的な親）＋クラスタ記事（個別の子）**で束ねる。Google にもAIにも「このサイトはこの領域の専門家」と伝わる。

```
[ピラー] シフト管理の完全ガイド（網羅的・主軸KW）
   ├─ [クラスタ] 飲食店のシフト作成のコツ
   ├─ [クラスタ] シフト管理アプリの選び方（比較）
   ├─ [クラスタ] シフトの希望提出を効率化する方法
   └─ [クラスタ] 労務トラブルを防ぐシフトの組み方
   ↑ 各クラスタ → ピラーへ内部リンク。ピラー → 各クラスタへ内部リンク。
```

- クラスタ記事は必ずピラーへリンクし、ピラーは全クラスタへリンク
- アンカーテキストは「ここをクリック」ではなく**対象を表す語**にする
- CV（料金・トライアル）への内部リンクを各記事の文脈で自然に置く

## 5. E-E-A-T（コンテンツの信頼性）

Google の品質評価軸＝**Experience（経験）/ Expertise（専門性）/ Authoritativeness（権威性）/ Trust（信頼）**。AI が引用したくなる「明快さ」とも一致する。実装で示す：

- **経験/専門性**：著者情報（誰が書いたか・実績）を `Article` schema の `author` と本文の署名で明示
- **権威性**：一次情報・統計・出典の引用、導入実績・事例
- **信頼**：運営者情報（特商法・会社概要）、最終更新日、問い合わせ導線、HTTPS
- **YMYL注意**：お金・健康・法務に関わる SaaS（会計・労務・医療系）は信頼性要求が特に高い。監修者・出典を厚く

## 6. コンテンツの書き方（順位とAI引用の両取り）

```
✅ 結論を最初に書く（AI Overviews / スニペットに抜かれやすい）
✅ 1見出し1論点。h2/h3 を検索クエリ・PAAの言葉に合わせる
✅ 数値・固有名詞・出典を具体的に（「多くの」→「導入店舗の82%が」）
✅ Q&A形式の節を入れる（FAQ schema + AI引用の両方に効く）
✅ 表・箇条書きで構造化（機械可読性が上がる）
❌ 抽象的・冗長な前置き、キーワードの詰め込み（不自然な繰り返し）
```

## 7. ローカルSEO（店舗・地域型 SaaS / クライアント向け）

野口さんの顧客は飲食・小売など**地域店舗**が多い。店舗集客を支援する場面では：

- **Google ビジネスプロフィール**：登録・カテゴリ・営業時間・写真・投稿・クチコミ返信
- **NAP の統一**：店名（Name）・住所（Address）・電話（Phone）をサイト/各媒体で完全一致させる
- **`LocalBusiness` 構造化データ**：住所・営業時間・地図（`structured-data.md` 参照）
- **地域キーワード**：「渋谷 居酒屋 予約」のような地名 × 業種 × 行動
- SaaS 自体が「店舗のローカルSEOを支援する機能」を持つ場合、その価値訴求にもなる

- [ ] 1ページ1意図になっている（意図の混在なし）
- [ ] ピラー＋クラスタの内部リンク構造を設計した
