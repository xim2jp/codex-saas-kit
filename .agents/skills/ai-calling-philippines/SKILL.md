# AI 通話 Skill（フィリピン国内対応）

人間と AI が**音声通話でリアルタイムに会話する**システムを、**フィリピン国内での利用を前提**に設計・構築するための知識集。受電（インバウンド：問い合わせ・予約・FAQ）と架電（アウトバウンド：リマインド・督促・調査・一次営業）の両方を対象とする。

**「AI 通話」は単一の技術ではなく、音声認識（STT）・大規模言語モデル（LLM）・音声合成（TTS）・電話網（PSTN）接続・リアルタイム制御の合成物**である。この Skill は「どのサービスを使うか」「コストはいくらか」「フィリピンの言語（英語/タガログ語/ビサヤ語/タグリッシュ）の精度はどうか」「一般電話とつなげるか」「法令は何を守るか」を一望できるようにする。

> 日本国内対応の案件では `ai-calling-japan` Skill を参照する。言語・電話番号制度・法令（電気通信事業法/特定商取引法/個人情報保護法）が根本的に異なるため、Skill を分けている。
>
> **フィリピン特有の文脈**：フィリピンは世界有数の BPO（コールセンター）大国。AI 通話案件は「(a) フィリピン国内の顧客に英語/タガログ語/ビサヤ語で対応する」だけでなく、「(b) フィリピン拠点が海外クライアント向けに通話業務を担う」形でも現れる。本 Skill は (a) のフィリピン国内対応を主軸に置きつつ、(b) のデータ越境の論点も扱う。

## いつこの Skill を参照するか

- **要件定義**（Phase 1）：「電話を AI で受けたい/かけたい」要望の実現性・方式・コストを見極める時
- **技術スタック選定**（Phase 3）：カスケード型/音声対話型、マネージド/自作、PSTN プロバイダの選定を ADR 化する時
- **外部設計**（Phase 5）：通話フロー（会話シナリオ）、IVR/エスカレーション、画面（管理 UI・通話履歴）設計時
- **内部設計**（Phase 7）：常駐プロセスの置き場所、Webhook、録音/文字起こしの保存、状態管理設計時
- **テスト計画**（Phase 9）：通話品質・精度・レイテンシ・シナリオ網羅のテスト戦略策定時
- **実装**（Phase 11）：音声エージェント・Webhook・通話発信 API を実装する時
- **テスト**（Phase 11-12）：テスト架電、シナリオ評価（eval）、負荷/同時通話数の検証時
- **本番運用**：電話番号取得、開示文言、録音同意、監視ダッシュボード設計時
- **レビュー**（Phase 14）：録音同意（盗聴禁止法）・データ保護・エスカレーション経路・コスト上限の確認時

## 重要原則（必読）

### 1. 「AI 通話」を最初に 2 つの方式に切り分ける

| | カスケード型（パイプライン） | 音声対話型（Speech-to-Speech / Realtime） |
|--|---------------------------|------------------------------------------|
| 構成 | STT → LLM → TTS を直列に繋ぐ | 単一のマルチモーダルモデルが音声を直接入出力 |
| 代表 | Deepgram + Claude/GPT + ElevenLabs | OpenAI Realtime（gpt-realtime）、Gemini Live、**Amazon Nova Sonic（Bedrock）** |
| 長所 | 部品を差し替え可、LLM を自由選択、テキスト LLM は安い、文字起こしが正本 | 低レイテンシ、割り込み（barge-in）に強い、声のトーン・間が自然 |
| 短所 | レイテンシが積み上がる、感情・抑揚が落ちる | モデル選択肢が少ない、発話を厳密制御しにくい、音声トークン課金が高め |

> **基本方針**：会話の自然さ・低レイテンシ最優先なら音声対話型。発話内容の厳密な制御・好きな LLM・安価さ重視ならカスケード型。要件定義で必ず決める。詳細は `references/voice-ai-architecture.md`。

### 2. リアルタイム音声処理は Vercel / Supabase Edge では動かせない

音声エージェントは**通話が続く間ずっと WebSocket/WebRTC 接続を保持する常駐プロセス**を必要とする。Vercel の Serverless Functions・Supabase Edge Functions は短命で長時間接続を保持できないため、**音声ループをそこに載せてはいけない**。選択肢は 2 つ：

- **マネージドプラットフォーム**（Vapi / Retell 等）に音声ループを任せる（野口さん Tier A 向き）
- **常駐コンテナ**（**ECS Fargate** / Fly.io 等）に LiveKit Agents / Pipecat を載せる（野口さん Tier B 向き）

これが AI 通話案件で**最重要のアーキテクチャ判断**。詳細は `references/service-landscape.md`。

### 3. 言語は「英語・タガログ語・ビサヤ語・タグリッシュ」を最初に確定する

フィリピンには英語・フィリピン語（タガログ語ベースの国語）に加え、**「方言」ではなく独立した多数の言語**がある。なかでも**ビサヤ語（ビサヤ諸語。代表はセブアノ語）は地方言語で話者人口が最大**で、ビサヤ諸島（セブ・ボホール等）・ミンダナオ島の広域で日常語。対象地域がビサヤ諸島・ミンダナオなら、タガログ語前提の設計はユーザーの大半を取りこぼす。

- **英語（フィリピン英語）**：公用語で全国に通じる。米国英語向けモデルはフィリピン訛りで精度が落ちる
- **タガログ語/フィリピン語**：国語。ルソン島・首都圏で優勢。主要 STT の対応は限定的
- **ビサヤ語（セブアノ語）**：ビサヤ諸島・ミンダナオの広域で優勢。話者人口は地方言語で最大。**主要 STT/TTS の一級対応が乏しく、最重要かつ最も困難な対応領域**
- **タグリッシュ / ビスリッシュ（コードスイッチング）**：英語をタガログやセブアノに文中で混ぜる実会話の常態。多くの STT が苦手とする最難関
- その他のビサヤ諸語（ヒリガイノン語＝イロンゴ、ワライ語）・イロカノ語等：地域ごとに使われる

> **基本方針**：まず対象地域から言語を確定する（首都圏・ルソン島＝タガログ語/英語、ビサヤ諸島・ミンダナオ＝セブアノ語/英語）。全国対応なら**地域ベースの言語ルーティング**（着信の発信地域→既定言語）を設計する。ビサヤ語対応は STT/TTS の品質を電話品質の実音声で評価したうえで「どこまで対応するか」を要件決定にする。英語はビサヤ地域でも広く通じる中立的な既定言語になる。詳細は `references/cost-and-accuracy-ph.md`。

### 4. 一般電話（PSTN）接続にはフィリピンの電話番号取得が要る

「システムから一般の固定電話・携帯電話と通話する」には PSTN に繋がる電話番号が必要。フィリピンの番号取得には**本人・所在地の確認**が要り、**SIM 登録法（RA 11934）**を背景に番号と身元の紐付けが厳格化している。携帯番号（09xx）は CPaaS では原則扱えない。詳細・取得手続きは `references/telephony-philippines.md`。

### 5. 重要情報は必ず復唱確認する — 精度を信用しすぎない

フィリピン英語の訛り・タグリッシュのコードスイッチング・**電話音声の 8kHz 狭帯域**が重なり、STT 精度は理想条件より落ちる。氏名・電話番号・金額・日時・住所はミスが致命傷。

> **基本方針**：重要情報は AI に必ず復唱（confirm-back）させる。長い数字列は DTMF（プッシュ）入力も用意する。固有語（地名・人名・商品名）はキーワードブースト/カスタム辞書に登録する。詳細は `references/cost-and-accuracy-ph.md`。

### 6. 録音には全当事者の同意が要る（盗聴禁止法）

フィリピンの**盗聴禁止法（Anti-Wiretapping Act, RA 4200）**は、私的な会話を**当事者全員の同意なく録音すること**を犯罪としている。AI 通話で録音する場合は、**通話の冒頭で録音を告知し同意を得る**ことが必須。詳細は `references/compliance-philippines.md`。

### 7. データ保護（DPA 2012）と AI 開示を守る

通話音声・文字起こしは個人情報。**Data Privacy Act of 2012（RA 10173）**と **NPC（National Privacy Commission）**の規律に従う。海外クライアント向け業務ではクライアント側の法（GDPR/APPI 等）も重なる。相手が AI と話していると分かるよう、通話冒頭で AI 応対である旨を述べる。詳細は `references/compliance-philippines.md`。

### 8. レイテンシ予算を最初に設計する

会話が自然に感じる応答レイテンシは**おおむね 800ms 以下、理想は約 500ms**。VAD/エンドポインティング（無音判定）・STT・LLM の TTFT・TTS の初音声の合算。**エンドポインティングの無音しきい値**が体感を大きく左右する。詳細は `references/voice-ai-architecture.md`。

### 9. 人間（エージェント）へのエスカレーション経路を必ず設計する

フィリピンは人手のコールセンター文化が成熟しており、AI が詰まったら人間エージェントへ転送できることが期待値。AI が「分からない」「STT 低信頼」「相手の苛立ち」「センシティブな話題」を検知したら**人へ転送（warm transfer）またはコールバック予約**へ逃がす。詳細は `references/implementation-and-ops.md`。

## エージェント別の使い方ガイド

### requirements-architect

- 「電話を AI で」要望に対し、**受電/架電のどちらか**、**会話シナリオの複雑さ**、**月間想定通話分数**、**対象地域と対象言語（英語/タガログ語/ビサヤ語/タグリッシュ）**、**既存電話番号の有無**を要件として確定する
- フィリピン国内向けか、海外クライアント向け業務かを切り分け、データ越境の論点を整理（`references/compliance-philippines.md`）
- 録音可否・録音同意・AI 開示を要件定義書に明記

### tech-stack-architect

- `docs/11-tech-stack/adr/NNNN-ai-calling.md` に記録：
  - **方式選定**：カスケード型 / 音声対話型（原則 1）
  - **構築方式**：マネージド（Vapi/Retell）/ 自作（LiveKit/Pipecat on ECS Fargate）（原則 2）
  - **PSTN プロバイダ**：Twilio / Amazon Connect / その他（`references/telephony-philippines.md`）
  - **対象言語と STT 選定**（`references/cost-and-accuracy-ph.md`）
- ADR に「想定通話分数 × 分単価」のコスト試算と、**人手エージェント費との比較**を必ず添付（`references/cost-and-accuracy-ph.md`）

### external-designer

- **会話フロー（シナリオ）**を画面遷移図と同じ粒度で設計：挨拶・録音同意 → 本人/用件確認 → 分岐 → 復唱確認 → クロージング → エスカレーション
- 管理 UI の画面一覧：エージェント設定、通話履歴、文字起こし閲覧、録音再生、発信予約、ダッシュボード
- IVR・DTMF フォールバック・営業時間外・言語選択（英語/タガログ語/ビサヤ語）と地域ベースの言語ルーティングを設計

### internal-designer

- 常駐プロセスの置き場所（マネージド / ECS Fargate）を確定（原則 2）
- Webhook（通話開始/終了・文字起こし完了）の受け口と冪等化、録音/文字起こしの Supabase 保存、構造化アウトカム抽出を設計
- 関数呼び出し（予約・CRM 照会・RAG）とレイテンシ吸収を設計（`references/implementation-and-ops.md`）

### test-planner / tester

- テスト架電（人手 + LLM 駆動の模擬発信者）によるシナリオ評価を計画
- 精度（フィリピン英語・タガログ語・ビサヤ語・タグリッシュ・固有語・数値）・レイテンシ・割り込み・同時通話数のテスト観点を網羅
- 通話は決定的でないため eval（シナリオ合否・回帰）を中心に据える（`references/implementation-and-ops.md`）

### implementation-worker

- `references/service-landscape.md` の選定に従い実装。音声ループを Vercel/Supabase Edge に載せない（原則 2）
- 録音同意・重要情報の復唱確認を会話設計に組み込む（原則 5・6）
- API キー・チャネルシークレットはサーバ専用、フロントに出さない

### implementation-reviewer

- 録音同意（盗聴禁止法）、DPA 2012 対応、AI 開示、エスカレーション経路、コスト上限、Webhook 署名検証を確認

## SaaS 量産戦略への貢献

### BPO 大国フィリピンの電話業務を AI で置き換え/拡張する

フィリピンはコールセンター/BPO が基幹産業。AI 通話を SaaS に組み込めば、深夜帯・繁忙ピーク・定型業務（予約確認・督促・一次切り分け）を AI が担い、人間エージェントを高付加価値な対応に集中させられる。フィリピン国内の中小事業者向けにも、安価な受電自動化として展開できる。

### 1 ソース化と再利用

通話の会話ロジック（システムプロンプト・ツール・RAG）と Web/チャットのロジックはドメイン知識を共有できる。Supabase の顧客・予約データを通話とチャットの両方から使う 1 ソース構成を取る。`ai-calling-japan` と会話エンジンの構造を共有し、言語・電話・法令の層だけ差し替える。

### 売上直結フローを電話でも保証

- 受電：着信 → 録音同意 → 本人/用件確認 → FAQ/予約 → 取りこぼし時はコールバック予約
- 架電：リスト → 発信 → 会話 → アウトカム構造化 → CRM 反映
- これらを eval（Phase 12）でガードする

## アンチパターン（よくある失敗）

1. **音声ループを Vercel/Supabase Edge に載せる**：長時間接続を保持できず通話が切れる。常駐プロセスを使う
2. **対象地域の言語を無視する**：ビサヤ諸島・ミンダナオではセブアノ語（ビサヤ語）が日常語。タガログ語/米国英語前提の設計は大半のユーザーを取りこぼす。地域から言語を確定し、地域ベースの言語ルーティングを設計する
3. **録音同意を取らずに録音**：盗聴禁止法（RA 4200）違反は刑事罰。冒頭で同意を取る
4. **コストを試算せず本番投入**：分課金が積み上がる。フィリピンは人手が安く ROI 計算がシビア。人件費と必ず比較する
5. **重要情報を復唱確認しない**：誤認識のまま予約・金額が確定しクレームに。必ず復唱する
6. **AI 開示をしない**：信頼を損ね、反詐欺規制の強い環境でリスク。冒頭で開示する
7. **エスカレーション経路がない**：AI が詰まると顧客が孤立。人間エージェントへ逃がす導線を必ず作る
8. **DPA 2012 / NPC の規律を無視**：同意・利用目的・安全管理を欠くと違反。設計に織り込む
9. **海外クライアント向け業務でクライアント側の法を見落とす**：GDPR/APPI 等とデータ越境を整理する
10. **携帯番号（09xx）を CPaaS で大量取得しようとする**：原則発番されない。固定/地理番号で設計
11. **エンドポインティングを既定のまま放置**：話の途中で割り込む/沈黙が長い。無音しきい値を調整
12. **AI 通話を緊急通報の代替にする**：CPaaS 番号は緊急通報に繋がらないことが多い
13. **ビサヤ語の発話をタガログ語 TTS で読み上げる**：別言語であり不自然・不正確。セブアノ語対応 TTS を実音声で評価し、無ければ英語に寄せる
14. **ビサヤ地域の利用者にタガログ語を既定言語として押し付ける**：受け取られ方が良くないことがある。英語を中立的な既定にし、セブアノ語対応を上乗せ価値とする
