# 一般電話（PSTN）接続とフィリピンの電話番号

「システムから一般の固定電話・携帯電話と通話できるか」「フィリピンの電話番号をどう取得するか」の指針。

> 番号取得の可否・必要書類・規制は CPaaS の規約改定や NTC の制度で変わる。**取得着手時に各社・NTC の最新情報を必ず確認**する。

## 結論：一般電話とつなげるか

**つなげる。** ただし PSTN（公衆電話網）に接続できる**電話番号と通話基盤（CPaaS / クラウド電話）**が要る。アプリ内 VoIP 通話だけなら番号は不要だが、本 Skill が想定する「電話で受ける/かける」は PSTN 接続が前提。

- **受電（インバウンド）**：自社が保有するフィリピンの番号への着信を AI が受ける
- **架電（アウトバウンド）**：自社の番号を発信者番号として、相手の固定/携帯にかける

## フィリピンの電話番号制度

| 種別 | 例 | CPaaS での取得 | 用途・特徴 |
|------|----|--------------|-----------|
| **地理的固定番号（地域番号）** | (02) メトロマニラ 等 + 加入者番号 | 取得可（本人/所在地確認が要る） | 受電/架電に使える。地域に紐づく |
| **モバイル番号** | 09xx-XXX-XXXX | **原則 CPaaS では発番されない** | キャリア/SIM に紐づく。後述の SIM 登録法の対象 |
| **トールフリー（1-800 等）** | 1-800-X | 取得可（条件あり） | 着信側課金。受電窓口向け |

> **設計上の含意**：フィリピンでも**携帯番号を CPaaS で大量に並べる運用はできない**前提で設計する。受電・架電は地理的固定番号やトールフリーを基盤にする。発信者番号がモバイル番号でないと出てもらいにくい場面はあるが、規制と取得制約から固定/地理番号で組むのが基本。

## SIM 登録法（RA 11934）という背景

フィリピンの **SIM Registration Act（RA 11934）**は、**すべての SIM カードを本人確認済みの身元に登録すること**を義務づける。これは詐欺電話・スミッシング対策として導入された。

- モバイル番号は身元と強く紐づく。匿名 SIM を束ねて発信する運用は法的にできない
- CPaaS の地理的固定番号でも、規制当局（NTC）は**「誰がどこで番号を使っているか」**を把握しようとする方向にある。番号取得時の本人・所在地確認はその一環
- フィリピンは詐欺電話・詐欺 SMS が社会問題化しており、**身元不明の発信に対する規制・ブロックが強化される傾向**。AI 通話システムは「正規の事業者が透明に使っている」ことを示せる構成にする

## PSTN プロバイダ（通話基盤）の選択肢

| プロバイダ | フィリピンの番号 | 特徴 |
|-----------|----------------|------|
| **Twilio** | フィリピンのローカル番号を提供 | 世界標準の CPaaS。番号取得に**規制要件（エンドユーザーの身元・所在地確認の書類）**が要る。番号在庫は時期により変動 |
| **Amazon Connect** | リージョン・国により提供番号が異なる | AWS のクラウドコンタクトセンター。提供可否を要確認。Bedrock と統合しやすい |
| **Vonage / Plivo 等の海外 CPaaS** | 番号により可否が異なる | フィリピン番号の在庫・規制対応はプロバイダ差が大きい |
| **フィリピン国内の通信事業者 / VoIP 事業者** | 地理番号・トールフリーに強い | 国内事業者は NTC 対応・番号取得の相談がしやすい。BPO 向けの回線提供実績が豊富 |

> **野口さん向けの目安**：マネージドプラットフォーム（Vapi/Retell）に任せる場合、多くは Twilio を裏で使う。番号在庫・規制要件はフィリピン番号で特に変動しやすいため、**プロジェクト初期に「希望する番号種別が今この瞬間に取得できるか」をプロバイダに確認**する。

## 番号取得の実務（Twilio の例）

1. **規制バンドル（Regulatory Bundle）の作成**：フィリピン番号は**エンドユーザー（実際に番号を使う主体）の身元・所在地**を示す書類提出が要る。規制当局は「誰が・どこで」使うかを重視する
2. 審査の通過を待つ（即時ではない。スケジュールに織り込む）
3. 番号を購入し、Voice の Webhook / SIP / アプリに紐付け
4. 発信者番号として使う番号は**自社が正当に保有する番号のみ**。番号偽装（スプーフィング）はしない

国内事業者・Amazon Connect でも、本人・所在地確認の考え方は同様。**「番号がすぐ手に入る」前提でスケジュールを組まない**。

## SIP トランク / SIP 接続

自作構成（LiveKit Agents / Pipecat）で電話と繋ぐとき、CPaaS が提供する **SIP トランク**経由で音声を常駐コンテナに引き込む。

- LiveKit Cloud は **SIP（インバウンド/アウトバウンド）**をサポートし、PSTN ↔ WebRTC を橋渡しする
- Twilio の **Elastic SIP Trunking** で SIP 経由の発着信を構成できる
- フィリピンは BPO 向けの SIP/VoIP 終端が成熟しており、国内事業者の SIP トランクを使う選択肢も現実的

## NTC（国家電気通信委員会）

NTC（National Telecommunications Commission）はフィリピンの電気通信を所管する。

- 電気通信事業・付加価値サービスの規制、番号資源の管理
- 詐欺電話・スパム対策の取り組み（不正な発信のブロック、発信者表示の整備など）が進行
- 「通話サービスを第三者に提供する」形態（SaaS として顧客の代わりに発着信する等）では、NTC の登録・許認可が関わる可能性がある。**形態が固まった段階で要確認**

## 発信者番号と応答率（架電の設計）

- **発信者番号の表示**：見知らぬ番号・非通知は出られにくい。詐欺電話が多い環境のため、正規の番号・ブランド表示が応答率に効く
- **発信時刻**：常識的な時間帯に限定する
- **再架電**：不在・拒否のリストを管理し、過度な再架電をしない（苦情・反詐欺規制の観点）

## 受電の設計

- **着信ルーティング**：営業時間内は AI、時間外は留守電/コールバック予約、AI が無理なら人間エージェントへ転送
- **言語選択・地域ルーティング**：発信地域（市外局番・エリア）から既定言語を推定する（首都圏=タガログ/英語、ビサヤ諸島・ミンダナオ=セブアノ/英語）。冒頭で英語/タガログ語/ビサヤ語を選ばせる設計も併用（`cost-and-accuracy-ph.md`）
- **IVR / DTMF**：数字の聞き取りミスを避ける場面で有効
- **同時着信数**：CPaaS/プラットフォームの同時通話上限（チャネル数）を超えると話中になる。ピークで見積もる

## 緊急通報の制約（必読）

CPaaS / VoIP 番号は**緊急通報（フィリピンの緊急番号 911 等）に発信できない**ことが多い。AI 通話システムを緊急連絡の手段として設計・案内してはいけない。

## レビュー観点

- [ ] 一般電話接続の要否を確定（PSTN か、アプリ内 VoIP のみか）
- [ ] 使う番号種別（地理的固定番号 / トールフリー）を決定（モバイル番号は CPaaS では原則不可と理解）
- [ ] 番号取得に必要な書類（エンドユーザーの身元・所在地）・審査期間をスケジュールに織り込んだ
- [ ] PSTN プロバイダ（Twilio / Amazon Connect / 国内事業者）を選定し、希望番号の在庫を初期に確認
- [ ] 発信者番号が自社の正当な保有番号で、偽装していない
- [ ] 「通話サービスを第三者に提供する」形態なら NTC の許認可要否を確認
- [ ] 架電の時間帯・再架電ルールを設計
- [ ] 同時通話数（チャネル数）をピーク想定で見積もり
- [ ] 緊急通報の代替にしていない
