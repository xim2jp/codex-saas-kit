# 実装・テスト・運用（野口さんスタック）

AI 通話システムを野口さんスタックに実装し、テスト（eval）・運用するための指針。フィリピン国内対応の観点を含む。

## アーキテクチャの骨格

音声のリアルタイムループ（常駐プロセス）と、それ以外（管理 UI・記録・分析）を分ける。

```
┌─ リアルタイム層（常駐）──────────────┐   ┌─ アプリ層（Vercel/Supabase）─────────┐
│ マネージド（Vapi/Retell）            │   │ Next.js 管理UI：エージェント設定      │
│  または                              │   │   通話履歴・文字起こし閲覧・架電予約  │
│ ECS Fargate（LiveKit/Pipecat）       │──→│ Route Handler：Webhook 受信           │
│  + Bedrock（Nova Sonic / Claude）    │   │ Supabase：通話記録/文字起こし/録音   │
└──────────────────────────────────────┘   │ Edge Function/バッチ：通話後の要約    │
                                            └───────────────────────────────────────┘
```

- リアルタイム層は **Vercel/Supabase Edge に置かない**（長時間接続を保持できない。`service-landscape.md`）
- アプリ層は野口さん Tier A（Next.js + Supabase）にそのまま乗る

## データモデル（Supabase）

最小構成のテーブル例：

| テーブル | 主な列 | 備考 |
|---------|-------|------|
| `calls` | id, direction（inbound/outbound）, from, to, started_at, ended_at, duration_sec, status, outcome, language, tenant_id | 1 通話 1 行。使用言語も保持 |
| `call_transcripts` | call_id, turn_index, role（user/agent）, text, confidence, ts | ターン単位の文字起こし |
| `call_recordings` | call_id, storage_path, duration_sec, **consent_obtained**, retention_until | 録音は Supabase Storage、メタを行に。**録音同意フラグを必ず持つ** |
| `call_outcomes` | call_id, 構造化フィールド（予約日時・要件区分・要対応フラグ等） | 通話後抽出（後述） |
| `dnc_list` | phone, reason, created_at, tenant_id | 架電拒否リスト |

- **RLS でテナント分離**（`tenant_id`）。マルチテナント SaaS の前提
- 録音/文字起こしは個人情報。アクセス権を絞り、`retention_until` で保持期限を管理（`compliance-philippines.md`）
- **`consent_obtained`**：盗聴禁止法（RA 4200）対応。同意が取れた通話のみ録音を保持する

## 録音同意の実装（フィリピン必須）

盗聴禁止法（RA 4200）により、録音には全当事者の同意が要る。

1. 通話冒頭で録音告知 → 相手の同意/不同意を聞く
2. **同意が取れたら録音開始**。取れなければ録音せず通話継続（または別フロー）
3. 同意の有無・時刻を `calls` / `call_recordings` に記録
4. 同意なし通話の録音データを誤って保存しない（パイプライン側で録音オフ）

## 言語の選択とルーティング

フィリピンは地域で主要言語が異なる（首都圏＝タガログ/英語、ビサヤ諸島・ミンダナオ＝セブアノ/英語）。`calls.language` に確定言語を保存し、次の順で決める：

1. **地域ベースのルーティング**：着信の発信地域（市外局番・エリア）から既定言語を推定する
2. **冒頭の言語選択**：英語／タガログ語／セブアノ語を相手に選ばせる（IVR または発話）
3. **会話中の検出**：相手の発話言語を検出し、STT/TTS・プロンプトの言語を切り替える
4. **既定は英語**：低リソース言語（セブアノ等）の STT/TTS 品質が不足する場面の安全な既定。**ビサヤ地域でタガログ語を既定にしない**（`cost-and-accuracy-ph.md`）

セブアノ語など対応の薄い言語は、エスカレーション先にその言語の話者エージェントを用意しておく。確定言語に応じて STT/TTS/システムプロンプトを切り替え、通話後の構造化抽出にも `language` を引き継ぐ。

## Webhook の受信

通話プラットフォーム/コンテナは「通話開始」「通話終了」「文字起こし完了」「録音準備完了」などのイベントを Webhook で送る。Next.js の Route Handler で受ける。

- **署名検証**：プラットフォームの署名（HMAC 等）を**生ボディ**で検証してから処理。検証なしの実装は脆弱性
- **冪等化**：イベント ID で重複処理を防ぐ（再送される前提）
- **即時 200 応答**：重い処理は 200 を返してから非同期で
- 機微キー（API キー・チャネルシークレット）はサーバ専用。フロントに出さない

## 架電（アウトバウンド）のトリガ

管理 UI / バッチから「この番号にかけて」をプラットフォーム API（REST）に投げる。

- 発信前に **DNC リスト（拒否リスト）を照合**し、拒否番号には発信しない
- 発信時刻を常識的な時間帯に制限
- 発信レート（同時数・1 分あたり）を絞り、苦情・コスト暴走・回線逼迫を防ぐ
- フィリピンは詐欺電話への警戒が強い。発信者番号・冒頭の名乗りで**正規事業者であることを明確に**示す

## ツール（関数呼び出し）の実装

会話中に LLM が呼ぶ関数：空き枠照会・予約確定・顧客照会・ナレッジ検索（RAG）・人間エージェントへのエスカレーション。

- 副作用のあるツール（予約確定・決済）は**冪等**にする
- ツール実行が長いときは**つなぎ発話**でレイテンシを吸収（`voice-ai-architecture.md`）
- ツールの失敗時の発話を必ず用意
- LLM に事実を作らせない：価格・在庫・規約は**ツール/RAG の結果のみ**を根拠に話させる

## 人間エージェントへのエスカレーション

AI が次を検知したら人へ逃がす：明示的な要求（"I'd like to speak to a person"）/ STT・解釈の低信頼が続く / 苛立ち・クレーム / センシティブな話題 / シナリオ外。

- **ウォーム転送（warm transfer）**：SIP 転送で人間エージェントに繋ぐ。可能なら通話の要約を引き継ぐ
- **コールバック予約**：人が出られない時間帯は、相手の希望時間で折り返し予約を作る
- フィリピンは人手のコールセンター文化が成熟しており、AI と人間のハイブリッド運用が現実的。エスカレーション無しの AI 通話は重大なクレーム源

## 通話後処理（非同期）

リアルタイムでなくてよい処理は通話後に回す（Supabase Edge Function / バッチ）。

- **文字起こしの整形・要約**：全文を LLM で読み直し、誤認識を文脈補正し要約
- **構造化アウトカム抽出**：予約日時・要件区分・対応要否などを構造化して `call_outcomes` へ
- **CRM/業務システム連携**：抽出結果を反映
- **品質スコアリング**：シナリオ遵守・解決率などを集計

## 監視・観測

通話ごとに記録・可視化する指標：

- 応答レイテンシ（`voice-ai-architecture.md` の目標 800ms 以下）、TTFT
- 割り込み回数、STT 平均信頼度、使用言語
- 通話時間、エスカレーション率、タスク成功率（予約成立率等）
- コスト（通話あたり・日次・月次）と予算アラート

## テストと eval

会話は決定的でないため、従来のユニットテストだけでは品質を担保できない。**多層で**テストする。

| 層 | 対象 | 方法 |
|----|------|------|
| ユニット | ツール関数、プロンプト構築、通話後抽出ロジック | Vitest 等 |
| 統合 | Webhook ハンドラ、DB 書き込み、署名検証、冪等化、録音同意フラグ | Vitest + モック |
| シナリオ eval | 会話全体の合否 | **LLM 駆動の模擬発信者**でシナリオを多数自動実行し、達成基準（予約が取れた・正しく断った・正しくエスカレーションした・録音同意を取れた）で採点 |
| テスト架電 | 実電話での通し確認 | 実番号にかけて人手 QA。電話品質・8kHz・割り込み・**フィリピン英語/タグリッシュ**・固有語を実環境で確認 |
| 負荷 | 同時通話数 | 想定ピークでの同時接続・話中率 |

- **回帰**：プロンプト/モデル/STT を変えたらシナリオ eval を再実行し劣化を検出
- マネージドプラットフォームの test suite 機能、LiveKit/Pipecat のテスト機構も活用
- 本フレームワークの Phase 12（ユースケース E2E）では、Web の Playwright に代えて/加えて**テスト架電 + シナリオ eval** をユースケース検証として位置づける

## 失敗モードと対処

| 失敗 | 対処 |
|------|------|
| 訛り・タグリッシュで STT がゴミを返す | 復唱確認、聞き返し、英語へ誘導、低信頼でエスカレーション |
| LLM のレイテンシ急増 | つなぎ発話、タイムアウトと定型フォールバック |
| TTS 障害 | フォールバック音声、定型音声の事前録音 |
| 通話切断 | 再架電/コールバック予約、途中状態の保存 |
| ツールのタイムアウト | 失敗時発話、後追いコールバック |
| 録音同意が取れない | 録音をオフにして通話継続、または別手段案内 |
| コスト暴走 | 最大通話長・無音タイムアウト・予算アラート（`cost-and-accuracy-ph.md`） |

## レビュー観点

- [ ] リアルタイム層が常駐プロセスにあり Vercel/Supabase Edge に載っていない
- [ ] Webhook が署名検証・冪等化・即時 200 応答になっている
- [ ] 録音同意フラグを持ち、同意が取れた通話のみ録音を保持している
- [ ] 録音/文字起こしが暗号化保存・RLS 分離・保持期限管理されている
- [ ] 対象地域に応じた言語ルーティングがあり、`calls.language` に確定言語を保存している
- [ ] 架電前に DNC リストを照合している
- [ ] 副作用ツールが冪等で、失敗時発話がある
- [ ] 人間エージェントへのエスカレーション（転送/コールバック）が実装されている
- [ ] 通話後の要約・構造化抽出・CRM 連携が設計されている
- [ ] レイテンシ・コスト・成功率の監視と予算アラートがある
- [ ] シナリオ eval + テスト架電で品質を検証し、回帰の仕組みがある
